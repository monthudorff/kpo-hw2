# КПО. ДЗ №2. ПОС — Преподавательская оценка студентов

## Назначение и возможности

Консольная ведомость одного курса: добавление и просмотр студентов и критериев, выставление,
просмотр, исправление и отмена оценок, расчёт итогов и экспорт в CSV. Меню и сообщения на русском.
Ошибка ввода или записи файла возвращает пользователя в меню; конец ввода завершает работу.

## Доменная модель и инварианты

`Gradebook` — корень агрегата для одного курса: хранит студентов, рубрикатор и актуальные оценки.
`Student` и `Criterion` — сущности с локальными целочисленными ID. `Evaluation` — неизменяемый факт
оценивания пары студент–критерий; при исправлении заменяется целиком. `FinalScore` — Value Object,
снимок результата расчёта. Коллекции наружу выдаются неизменяемыми копиями.

Агрегат проверяет наличие студента и критерия, запрещает повторное выставление, исправление и отмену
отсутствующей оценки. `Evaluation` проверяет конечность балла и диапазон `[0, maxScore]`.
Создать или вставить оценку через публичный конструктор нельзя. Критерий создаётся Builder-ом:
название непустое, максимум конечный и положительный, вес конечный и неотрицательный.

## Расчёт итога и принятые допущения

Domain Service `FinalScoreService` применяет стратегию `WeightedScorePolicy`:

```text
итог = 10 × sum(weight × score / maxScore) / sum(weight)
```

Знаменатель включает весь рубрикатор; пропуск оценки даёт ноль. Пустой рубрикатор и нулевая сумма
весов приводят к понятной доменной ошибке. Итог не хранится: каждый запрос читает актуальные оценки.
Веса масштабируются на максимальный вес, чтобы избежать переполнения при сложении больших чисел.
Числа хранятся в `double`; округление предусмотрено только при выводе.

ID выдаются последовательно и независимо для студентов и критериев; одинаковые имена и названия
допустимы, выбор выполняется по ID. Дробные числа вводятся с точкой или запятой. Вес 0 разрешён:
такой критерий не влияет на итог. Исправление и отмена доступны только для существующей оценки,
после отмены её можно выставить заново. Изменение и удаление студентов/критериев, несколько курсов,
история оценок и постоянное хранение в объём задания не включены.

CSV: UTF-8, разделитель запятая, CRLF, заголовок `student_id,student_name,final_score`.
Имя заключено в кавычки, внутренние кавычки удваиваются; итог выводится с точкой и двумя знаками.
Каталог должен существовать, существующий файл перезаписывается. Для пустого списка студентов
выводится сообщение, экспорт создаёт только заголовок. Данные ведомости теряются при выходе.

## Архитектура и зависимости

Облегчённая Ports and Adapters, исходники в `src/main/java/ru/hse/pos`:

| Пакет | Ответственность |
| --- | --- |
| `domain` | Агрегат, сущности, инварианты, расчёт итога |
| `application` | `GradebookApplication` и выходные порты `GradebookRepository`, `FinalScoreExporter` |
| `infrastructure` | `InMemoryGradebookRepository` и `CsvFinalScoreExporter` реализуют порты |
| `cli` | Чтение строк, меню, форматирование, обработка ошибок |
| `Main` | Composition root: настройка Guice и запуск |

Зависимости: `cli / infrastructure → application → domain`. Адаптеры также используют доменные
типы из внутренних слоёв. В `domain` и `application` нет зависимостей от Guice, консоли и файлов.
Порт репозитория возвращает один живой агрегат: изменения сохраняются в памяти этого экземпляра;
отдельный `save` для выбранного in-memory хранения не нужен.

## Паттерны GoF и их назначение

| Группа | Паттерн и место | Конкретная польза |
| --- | --- | --- |
| Порождающий | Builder — `Criterion.Builder` | Именованные шаги `maxScore` и `weight` помогают не перепутать два числовых параметра; неполный или некорректный критерий не проходит `build()`. Единственный конструктор закрыт и сам проверяет инварианты. |
| Структурный | Facade — `GradebookApplication` | Меню вызывает готовые сценарии, не связывает репозиторий, расчёт и экспорт самостоятельно; экспорт всегда получает свежие итоги. |
| Поведенческий | Strategy — `FinalScorePolicy` / `WeightedScorePolicy` | Формула отделена от обхода студентов в Domain Service и может быть подменена через DI без изменения сценариев и UI. |

`Evaluation.create` — внутренняя простая фабрика, отдельным GoF Factory Method не считается.

## DI-контейнер

Guice 7 собирает граф в `Main.PosModule`. Порты связаны с адаптерами, репозиторий имеет область
`Singleton`, поэтому все сценарии работают с одной ведомостью. Методы `@Provides` получают
зависимости от контейнера и передают их в конструкторы `FinalScoreService`, `GradebookApplication`
и `ConsoleMenu`. Обязательные зависимости — `final`, проверяются на `null`; field injection нет.

## Сборка и запуск

Нужен JDK 17 или новее. Maven Wrapper скачает Maven 3.9.11, если его ещё нет; первый запуск требует
интернет для Maven и зависимостей.

```bash
./mvnw clean verify
java -jar target/pos-1.0.0.jar
```

Windows: `mvnw.cmd clean verify`. При установленном Maven допустимо `mvn clean verify`.
Компилятор использует `--release 17`; JAR включает зависимости.

## Тестирование и пример работы

JUnit 5: 39 тестов (включая параметризованные случаи), независимые фикстуры, структура
Arrange–Act–Assert. Проверяются границы балла и выход за них, NaN/Infinity, неизвестные студент
и критерий, неполный Builder, защита коллекций, разные максимумы и веса, пропуски,
исправление/отмена и пересчёт, нулевая сумма весов, актуальность экспорта, CSV-экранирование,
ошибки файла, неверный ввод и EOF, сборка графа Guice и общий репозиторий.

Проверка: `./mvnw clean verify` на JDK 17 — 39 тестов, 0 ошибок, 0 пропусков.

Сквозной сценарий сохранён в `docs/demo-input.txt`. Запускать из корня проекта после сборки:

```bash
java -jar target/pos-1.0.0.jar < docs/demo-input.txt
cat target/demo-results.csv
```

Сценарий создаёт Анну Иванову и Бориса Петрова, критерии «Семинары» (максимум 10, вес 1)
и «Проект» (максимум 100, вес 3), показывает списки, выставляет и просматривает оценки.
Для Анны оценки 10 и 50 дают 6.25; исправление проекта на 100 — 10.00;
отмена семинаров — 7.50; повторное выставление 7,5 — 9.38 после округления.
У Бориса только 8 за семинары, поэтому итог — 2.00.

Проверены неверный пункт меню, нечисловой ID, балл 11 при максимуме 10, неизвестные студент
и критерий, расчёт при пустом рубрикаторе и попытка экспорта в каталог `target` вместо файла.
После каждого сообщения программа продолжает работу и успешно создаёт CSV:

```csv
student_id,student_name,final_score
1,"Анна Иванова",9.38
2,"Борис Петров",2.00
```

Содержимое фактического CSV дополнительно проверено стандартным CSV-парсером Python:
заголовок, имена, количество строк и итоговые значения совпадают. Сквозной прогон выполнен
на Java 17; запуск итогового JAR с активной Java 25 также проверен.

По итогу я обнаружил ошибки:

1. В Evaluation проверка score <= 0 отклоняет допустимый балл 0. Правильно: score < 0

2. В WeightedScorePolicy стоит continue для критериев без оценки. Из-за этого итог завышается: например, единственная оценка 10/10 при двух равновесных критериях даёт 10 вместо 5. Если оценок нет вообще, получается NaN. Нужно учитывать вес каждого критерия, а пропущенный балл считать нулём

3. Нарушено экранирование CSV. В CsvFinalScoreExporter имя оборачивается в кавычки, но внутренние кавычки не удваиваются. Например, имя "Анна "А"" записывается некорректно. Нужно восстановить value.replace("\"", "\"\"") перед обрамлением кавычками

Я усилил тесты и устранил ошибки.
