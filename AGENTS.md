Инструкции для выполнения ДЗ №2 «ПОС»

Подход

- Реализуй домашнее задание по инструкции из AGENTS.md на Java 17, Maven
- При необходимости обращайся к условию: docs/statement.pdf 
- Каркас отчета в README.md создан. По выполнении задания заполняй его
- На каждом этапе делай коммит
- Избегай оверинжениринга: важны рабочие сценарии и объяснимые решения
- Соблюдай SOLID, KISS, DRY, YAGNI
- Не спамь комментариями, они нужны только для неочевидных решений

Обязательные сценарии

- Добавить студента; добавить критерий с названием, максимумом баллов и весом; показать списки студентов и критериев
- Выставить, посмотреть, исправить и отменить оценку студента по критерию
- Рассчитать взвешенный итог из актуальных оценок и рубрикатора через Domain Service; экспортировать итоги в CSV
- Понятное консольное меню: ошибочный ввод не завершает программу, ошибки домена и файлов выводятся понятным сообщением

Домен и принятые допущения

- Единый язык: Student, Criterion, Evaluation, Gradebook, итог
- Для одного курса достаточно агрегата Gradebook
- Создай интерфейс GradebookRepository для работы с ведомостью и отдельный класс для её хранения в памяти
- Модель сама запрещает оценку неизвестного студента, критерия вне рубрикатора и балл вне [0, maxScore]
- Создание через фабрику не должно оставлять обходных путей нарушения правил
- Формула по умолчанию: итог = 10 * sum(weight * score / maxScore) / sum(weight) по всему рубрикатору
- Пропуск оценки даёт 0; нулевую сумму весов обработай понятной ошибкой

Архитектура и GoF

- Используй облегчённую Ports and Adapters: пакеты domain, application, infrastructure, cli; сборка зависимостей в Main 
- Зависимости: cli/infrastructure -> application -> domain; адаптеры реализуют внутренние порты
- Domain содержит модель, инварианты и расчёт итога; не зависит от консоли, файлов, DI и других фреймворков
- Application координирует сценарии, адаптеры отвечают за ввод/вывод и хранение
- DI-контейнер обязателен: используй Guice, внедряй обязательные зависимости через конструктор
- Для минимального объёма достаточно in-memory репозитория и CSV-экспорта через порт
- Реализуй по одному уместному GoF из каждой группы (максимум два в группе)
- Для каждого паттерна объясни конкретную пользу. Не выдавай простую фабрику за Factory Method

Проверка и сдача

- Напиши несколько независимых JUnit 5 тестов по Arrange–Act–Assert: 
  - границы балла и выход за них
  - неизвестный критерий
  - взвешивание с разными максимумами
  - пропуски
  - исправление/отмена и пересчёт
- Выполни сборку и тесты, затем сквозной консольный сценарий: студенты -> критерии -> оценки -> итог -> экспорт
- Проверь содержимое CSV и обработку неверного ввода
- Заполни существующие разделы README по фактической реализации. Кратко объясни принятые решения и их причины
- При необходимости согласуй добавление и редактирование разделов ридми
